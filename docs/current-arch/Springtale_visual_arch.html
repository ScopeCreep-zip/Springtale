Phase 3: Veilid DHT
Distributed registry
SMPL record (o_cnt: 0, 255 subkeys). Each author writes signed manifest to own subkey. Readers verify Ed25519 before load. watch_dht_values for update notification.
manifest signing flow
Connector author
Sign manifest with Ed25519 private key
Canonical JSON of manifest fields (excluding signature field itself) is signed. Author pubkey included in manifest.
Registry
Store manifest + signature + pubkey
Registry maintains key→author map. TrustStore records known author pubkeys and trust levels. Phase 3: stored on Veilid DHT.

threat model
threat severity mitigation
Malicious community connector Critical Wasmtime Component Model sandbox. Fuel metering (10M instructions/call). 64 MiB memory cap. Capability allow-list checked at runtime by host. Ed25519 manifest sig verified before load. Guest cannot self-elevate.
Supply chain compromise (npm) Critical Rust for all trusted code. TypeScript only in sandboxed guest WASM. cargo-deny for license + advisory policy. Pinned Cargo.lock committed. No npm packages in host runtime.
Secret leakage via logs High secrecy::Secret<T> cannot impl Debug or Display. tracing subscriber redacts Secret values at subscriber level. All .expose_secret() call sites annotated with // SECURITY: comment.
Secret leakage via heap dump High zeroize::Zeroize on all key material. Memory zeroed on drop. No Secret<T> clone without explicit .expose_secret(). Zeroizing<T> wrapper on all SigningKey instances.
Connector privilege escalation High Capability grants are host-enforced at runtime. Guest WASM cannot call host functions not in its granted set. ShellExec requires blocking approval modal before connector loads — cannot be bypassed.
MITM on transport High rustls-tls exclusively — no native-tls or OpenSSL path. native-tls banned via Cargo.toml [patch]. TLS certificate validation never disabled in any code path. mTLS in Phase 2a HttpTransport.
Unsigned / tampered connector High Ed25519 signature verified against author pubkey before any load attempt. Registry maintains pubkey→author map. No unsigned connectors can load — hard error, not a warning (operations/connectors/install.rs; an unknown author is a hard error too). Caveat: first-party native connectors register through inventory at compile time and never pass through this gate — it covers installed and WASM connectors.
Credential exfiltration via connector High NetworkOutbound capability must list exact hostnames. No wildcards permitted in capability declarations. Sandbox WASI networking layer blocks connections to any host not in the granted set.
Connector CPU / memory DoS Medium Wasmtime fuel metering: 10M instructions per invocation. 64 MiB memory limit enforced by ResourceLimiter. Exceeding either limit traps the WASM instance — connector moves to Faulted state.
Prompt injection via AI adapter Medium AiRequest is a closed enum — AI backend never receives raw connector output or user secrets. Structured typed requests only cross the AI boundary. NoopAdapter (default) eliminates this attack surface entirely.
DHT registry poisoning (Phase 3) High Ed25519 manifest signatures verified before any connector load, regardless of registry backend. Author pubkeys pinned in TrustStore. Malicious DHT writes are rejected at signature verification — same check as PostgreSQL-backed registry. SMPL subkey ownership ensures only the author can write to their slot.
Recursive pipeline resource exhaustion Medium Child pipelines inherit fractional fuel budget (parent_fuel / 4). Max recursive depth configurable (default: 4 levels). Children inherit read-only parent context snapshots — no mutable shared state. Total fuel consumption bounded by root pipeline budget regardless of recursion depth.
Rogue bot in Rekindle community (Phase 3) Medium Rekindle §31 APAS model: bots are members with same CRDT merge rules. Permission enforcement is client-side — every honest reader validates the writer's role before accepting governance entries. A rogue bot's writes are ignored by all honest clients. Governance can ban the bot's pseudonym.

radicalkjax
design philosophy — classical bot architecture, bring your own AI
The bot IS the product. Users talk to it through chat platforms. Command routing is deterministic — same patterns as IRC/Discord/Telegram bots for decades.

Springtale does not provide AI. Users bring their own — Ollama on their machine, an OpenAI key, a Claude key, a local llama.cpp server. We provide the socket (AiAdapter trait). The LLM/agent is detachable (malwarevangelist-bot pattern).

OpenClaw: user says "search tokyo weather" → LLM decides to call search tool → API call → LLM formats result. Three calls, latency, cost, dependency.
Springtale: user says /search tokyo weather → command router matches → calls connector-presearch → template formats result. One call, instant, free, works forever.

When the AI bubble pops: unplug the adapter. You keep every command, every scheduled task, every automation, every connector. Nothing breaks.
